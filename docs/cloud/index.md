# kernable Cloud

Your kernel runs right next to your code, in your own infrastructure, so reads and writes are
local and fast. kernable Cloud keeps it in sync: every change goes, sealed with your keys, to a copy
in the EU that your kernels anywhere follow, and it backs that copy up, monitors it and keeps it
current. kernable Cloud is in [Preview Access](/cloud/preview-access), by invitation.

- **Your code stays yours.** kernable Cloud never runs, builds or sees your code. Your services
  and kernels run wherever you run them.
- **A sealed copy.** Each writer sends what it writes to a copy at kernable Cloud, encrypted with a
  copy key only your kernels hold. kernable stores and forwards it and reads
  nothing.
- **Readers anywhere.** Read-only replicas in other sites or clouds follow the copy, with no
  connection into the writer's network.
- **In the EU.** Every copy and every backup is kept in the EU.
